实验日期：2026-10-12（UTC）。引擎固定为 `ee6a2aa7a66d8bf2609059aaf8a7c0fe22fe8683`；依赖第一轮实验提交 `f06081f04812db0e6e3650b0a7a5e5b2baa9bd1b`。本轮只增加实验目录，未修改引擎或第一轮文件。

## 设计与实际执行

开发集 4 题；正式集 24 题，由 8 道业务建模、8 道机制组合、4 道信息缺失、4 道能力边界题组成。任务采用业务文字描述，公开输入不标注类别。A 组获得 schema，B 组增加机制卡，C 组再增加编译、执行和轨迹反馈。每组 3 个全新上下文，每个上下文完成同一批 24 题；各次顺序不同，同一次各组顺序相同。共收到 **216 份初始回答**，其中 **144 个完整信息模型机会**。同一上下文内题目并非独立统计样本。

作者提交规范化模型配置，经既有 **Business IR → Core IR → Execution Plan → Python runtime** 管线计算；未生成新引擎机制。评分同时检查关键业务约束、事件时刻、终态、资源账本和输入指纹。每道正式可执行题另有一个预先冻结的参数变更及手工推导预期；控制器修改模型副本并重编译，用于检验机制表达，而非检验作者收到变更要求后的修改能力。

主实验 35 个冻结输入和修复实验 40 个冻结输入均通过 SHA-256 核验。58 个基线文件的 Git blob 校验通过，其中 56 个位于 `src/`；第一轮已提交的 64 个文件全部保持原样。216 份初始回答及 36 份澄清后回答与评分前封存哈希一致。详见 `audit.json`、`parent-integrity.json`。

## 结论边界与下一阶段

本轮比第一轮增加了业务表述、机制组合、重复运行和隐藏参数变更，支持在 `aircraft-bounded-events/v1` 已有机制内继续搭建需求到 IR 的实验服务。全部可执行题达到满分，意味着现有题集的区分能力不足；它不证明开放式复杂系统建模、未见领域泛化、原生 SIMLOX 等价或执行反馈增益，也没有验证生产系统的可靠性。

下一阶段先补足可区分的证据：由领域人员提供未参与题目设计的真实业务描述，独立标注约束与验收轨迹；加入多轮遗漏、冲突需求、边界时序和行为上隐蔽的错误模型；在新的留出集上冻结标准后再比较。将自动文本筛查的改进放到新版本，保留本轮原始结果。

产品接入作为后续阶段：先做受限入口，返回候选 IR、待确认假设和缺失信息，用户确认后进入隔离仿真作业，结果关联输入版本、编译产物及验收证据；未知机制明确返回能力缺口。本轮没有部署 Riffoid 或对外服务，也未创建独立模型 API 接入。正式接入前需补齐真实业务留出验收、调用身份、日志和可测的时延/费用数据。
