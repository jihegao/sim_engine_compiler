# D14.var03: item PM after reinstallation

This case extends the accepted [D14.var02/03 zero-age package](../D14-var02-03-zero-age-reinstallation-v1.0.0/cli-scope-signoff-2026-10-02.md) with one fourth two-hour mission at h44 and a 48-hour horizon. The [contract](contract.json) froze the h46 prediction before either native run. The [exact diff](exact-diff.json) verifies that each arm changes only the schedule, horizon, result windows and descriptive text relative to its accepted parent. The paired new inputs still differ only in `MaterielPM.MONIT` and description.

The monitored arm has a physical item ID0 that accumulated two operation hours on the first mission, was removed by the unrelated `SYS-SWAP` PMID at h10, overhauled and stocked, and then physically reinstalled at h34. Its fourth mission ends h46. If its separate `LRU-OP3` counter had reset during removal, stock, overhaul under `SYS-SWAP`, or reinstallation, two new operation hours would be below the three-hour interval. The native trace instead starts `LRU-OP3` at h46 and removes that same ID0. This supports a bounded inference that the distinct item PMID counter persisted through that route. Native output does not expose the counter value directly. The converted arm also starts its system-level `LRU-OP3` at h46, but creates a new object ID3 on removal.
