# J03 invalid distribution boundaries

This package separates one accepted input-test rejection from a native capability limitation. `J03.var05` changes only the second `PREP-DET` probability factor in accepted `J03.var01` seed-01 input from 0.5 to 0.4. The factors sum to 0.9. The installed manual says factors for a `DISTID` must sum to one and that the input test checks this. The excluded diagnostic probe and a separate fresh accepted session-0 SSH run both returned converter error #265, with a 4-byte output and no simulation report. This supports one exact invalid PFAC input on the pinned executable.

`J03.var06` changes only the first inner row in accepted `J03.var04` seed-01 input so `PREP-IN` refers to `PREP-OUT`, while `PREP-OUT` already refers to `PREP-IN`. Both excluded cycle probes imported and exported but their calculation child process exited `0xC00000FD` (stack overflow), leaving a 4-byte output, zero-byte run log and no report. The preserved GUI PID 13340 remained responsive. This is a reproducible limitation for this exact cyclic input, not an accepted rejection or simulation result. It does not establish how other cycles behave.

`build.py --check` verifies both accepted parent hashes, exact source deltas and input hashes. The guarded runners require authenticated session-0 SSH, the host-wide Issue #18 mutex, exact manual/dictionary/executable pins and the preserved GUI start identity. The initial diagnostic runner is archived in `review/probe_native_ssh_initial.ps1` because the repeat cycle probe used a second run ID. Each closure records the runner hash used for its run. Independent read-only replay passed 247/247 checks across the fresh accepted run and three excluded diagnostics, including 32 raw seals. Each cycle probe left one additional unsealed temporary SXI copy, separately hashed in the verdict and evidence index. Local ignored `runs/` holds raw input, native files, logs, invocation, closure and accepted validation; the evidence index publishes their IDs and SHA-256 hashes. `validate_probes.py` replays the three diagnostics, and `validate_pfac_acceptance.py RUN_DIRECTORY` replays the fresh accepted rejection.

The proprietary manual and database dictionary are hash-pinned and not included. The result does not establish other PFAC sums, other distribution types, all cyclic references, GUI visual behavior, or cross-engine parity.
