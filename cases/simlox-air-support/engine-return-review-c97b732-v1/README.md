## Windows test-tool portability finding

On 4700-3, `PYTHONPATH=src python -m experiments.simlox_pairing.check_tests` collected/executed 26 tests with zero skips: **24 passed, 2 errored** in `source_identity()`. A default Windows checkout first changed Git blob line endings. After restoring exact Git blob bytes, the two errors remained because `provenance.py` hashes `str(path.relative_to(ROOT))`: Windows backslash keys yield build digest `a20bb50e2db1c557351edfa52ca8f690a5529c4bcd50e8e59c3d62a2b77c579f`, while the pinned POSIX-key digest is `8b029a0a79495bbdadb7f133ff035eb19c564365fe1c6315b3ba56289496ded1`. The independent checker uses committed blobs and POSIX Git paths and passed. The isolated PR #22 checkout was returned to a clean detached HEAD; neither PR #22 nor the engine was changed. This is a **consumer provenance/test-tool portability defect**, with no observed runtime result defect. Coordinator's exact-head Linux CI readback supersedes the old PR #22 receipt's pending CI gate only. The Windows provenance test remains a separate follow-up for PR #22 owners.
