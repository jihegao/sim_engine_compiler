# SIMLOX 2017 手册审读：限制与待判明语义

这些记录来自本机手册与配套表字典。它们决定后续探针的设计；本次没有新增原生运行结论。
来源版本和 SHA-256 见 [来源清单](../manual-sources-v2.json)。页码为 PDF 的物理页，所引章节与印刷页一致。

| 编号 | 发现与来源 | 必须保留的案例或反例 |
|---|---|---|
| MR01 | PDF 称 `OperationalProfile`，表字典和现有回导使用 `OperationProfile`（p270；字典表名） | A09/K02 固定原生表名与别名关系，不能生成两张近义表 |
| MR02 | 首次/再次出动不是 `MissionPreparation` 的已确认原生键（p294–297） | B03 正式采用 `explicit-mission-type-v1`：以 `COLD-FIRST` 表达首波冷启动、以 `HOT-SORTIE` 表达后续热出动，并分别绑定保障工序。该合同仍待原生验收；同一 MTID 按历史出动序号自动切换继续作为未确认的独立能力边界 |
| MR03 | 传统 `ItemFailureRate/SystemFailureRate` 不接受 `MISSIONS/CALHOURS`（p245–247、257–259） | D02 分开传统暴露与 FailureMode 日历路线；D07 验证多 OPID；非法组合保留转换日志 |
| MR04 | `ItemStructure`、`MaterielStructure`、`SystemStructure` 的结构语义不同（p247–260） | G01/G02/G12/F01 分别验收拆换、频率传播和子系统；既有 403 嵌套 LRU 问题继续单列 |
| MR05 | 工序分解严格串行；自定义 `SubTaskType` 只增加时长和资源语义（p400–404） | B02/B05 不把自定义名称解释为新触发条件。CM/PM 多件更换的并行等待不等于任意并行工序图 |
| MR06 | 只有 `SPECIAL` 资源用于 SIMLOX；`STANDARD/ENABLER` 在共用模式中被忽略（p413–414） | C01/C02 使用正确原生资源类型；不支持的类型保留负例。资源类型不自动代表人员专业 |
| MR07 | PDF 输入字段章节未完整描述资源故障；字典 `ResourceStationData` 给出 `RMTBF/RFTT/RMDT/RMDTD`（p221、754；字典第673–681行） | C10 以字典候选完成 GUI、回导、两种时钟与故障恢复探针；字段存在不等于行为已通过 |
| MR08 | 时间/整数分布的 PDF 清单与字典不同，包含 `TRIANGULAR/TRIANG`、`LOGNORMAL/LOGNORM`、`NEGEXP/EXP` 等差异（p541–545） | J01–J03 逐项回导实际标识；整数以字典的 `DETERM/IRECT/POISSON` 为候选，不默认接受时间分布 |
| MR09 | AlternateUnit 初次调用与后续重试描述冲突（p187、308） | A18 设置备用单位稍后才有飞机，区分两种行为；未判明时不得冻结重试规则 |
| MR10 | START 依赖的 FIXED 角色在 p287 与 p188、289、292 描述不一致 | A13 分别改变先行/后续任务类型，记录转换与事件；不能只凭文字选一方 |
| MR11 | 默认任务周期的比较条件与示例不一致（p194–195） | A10 以 48/50 小时等具体示例校准；示例预期为设计值，未运行前不作 oracle |
| MR12 | RBD 切换期间从何时开始生成故障存在冲突（p199、456） | G05 保留“切换开始/结束”两假说及可判别探针。其他状态验收不关闭该差异 |
| MR13 | `MONIT` 个体 PM 与传统 ItemStructure/FRT CM 不兼容；预龄影响 PM，不等于指数故障老化（p204–210、373） | D14/G11 分开模型路线，记录个体年龄、库存取用次序和多计数器继承 |
| MR14 | `PMRF<1` 是随机换件，不表示每 n 次 PM 更换（p392–393）；PM 计数重置时刻有概述/字段措辞差异（p202、218、370） | D10/D11/D15 用事件证明重置、定期触发与换件概率；不能用概率模拟确定性的每 n 次规则 |
| MR15 | 传统拆借、RRF、冗余不能直接套到 FailureMode/显式 CM；永久拆解供件未建模（p192、223–225、462） | E13/E14/G10 保留适用模型限制及不支持反例，显式 CM 替换作为不同机制验收 |
| MR16 | `Changes*` 仅改变已有对象的指定字段，不能改任意拓扑；已开工作业、可靠性、补订周期生效规则各异（p481–523） | I05/I06/I07 分别验证；14 张表逐项覆盖，不能用一次准备时长变更代替全部方法 |
| MR17 | `ResourceAllocation` 正文字段别名、`RPROB` 类型、FailureMode 的旧 `TTYPE` 描述与当前字典有漂移 | C06/D06/I01 以字典和原生回导核对字段；不从重复说明段落推导额外可写字段 |
| MR18 | 地理显示不定义运输距离；UnitGroupMember.XTIME 只调整 STOTD；SystemTransfer.TFPRI 在本版未使用（p313–314、479–481、538–541） | A17/I04/K08 用配对输入证实作用范围，不能用这些字段模拟动态路由或抢占优先级 |
| MR19 | 损伤物项能否回修的概述与 REPF 字段存在措辞差异（p210、426–427） | H02 分别设 REPF=0/1，核对真实回修/报废链；物项 TYPE 不能替代损伤修复参数 |
| MR20 | 原 C03 教学合同是同编队的人员争用；独立准备分支使用错开任务和设备争用 | C03 保留 07:30 开始、每机30分钟、两人08:00/一人08:30 的待验证时间线。设备方案另设探针名与合同，不能冒充同一验收 |

缺机与资源延误的取消条件、嵌套结构与物理换件语义，仍按[既有问题索引](README.md)保留原证据。
新增方法的成功运行只关闭该方法明确提出的断言，不自动关闭 J35 取消、完整物料账或跨引擎等价问题。
