# G03 BSID add/exclude variants: bounded CLI signoff

**Decision:** `native_behavior_accepted_cli_scope` for native acceptance of a base system plus a `BSID` variant with either one added LRU (`G03.var01`) or one base LRU excluded by `QTYPM=0` (`G03.var02`), exact author-row import/export, and a successful mission flown by the variant SID. This package becomes `reusable_published` after merge to `simlox/main`. The full G03 acceptance, including observation of effective inherited structure and failure aggregation, remains open.

The direct parent is published A01, source SHA-256 `8bbd31d05630cc4a44c4b03b715d17e2f4a1ee1601352952089efd3e584f98b7`. The installed SIMLOX 2017 manual SHA-256 `39427027c46809a9ce9ebcb9be04e7396d96746e42a6f8c7c0ba2ddc294ef8a3` says on printed pp. 253 and 256–257 that `BSID` variants inherit base items and add or exclude items through `ItemStructure`, with `QTYPM=0` for exclusion; `CBSID` configurations cannot exclude. The manual supports the source geometry, while the observed native report alone does not list the effective item breakdown.

The [pre-run contract](contract.json) SHA-256 `8ba24c2a6afca15635226a27dd669ffac1eb6df45c8ff14f8d5617bbb9552bb3` and [exact diff](exact-diff.json) freeze the A01 changes. The add input SHA-256 is `82e7b380402fc1e91afa3ffb104b6e99220094cf2fe3139a6c13a74e4a6327ad`; the exclude input SHA-256 is `79622dcc60d7172b3d09812f82e581d2e8a9f779790f24ab236508916a3875c2`. Both change only ProblemDescription, System, Item, ItemStructure, SystemDeployment and Unit; `BSID` points to `TEACH-AIR-01`, `CBSID` stays empty, and only the variant SID is deployed. The base item row has `QTYPM=1`; the variant row adds `TEACH-LRU-ADD` at `QTYPM=1` or excludes `TEACH-LRU-BASE` at `QTYPM=0`.

Fresh `g03-add-v101-20261001-01` and `g03-exclude-v101-20261001-01` runs each passed guarded native import, export, calculation, default JSON report and roundtrip check with zero conversion errors. Warning #108 reflects event logging; warning #2053 records the deliberately zero FRT of each defined item. In both logs, the variant is allocated at hour 7, launches at 8 and returns successfully at 10. Each report has 72 half-hour System and Stock bins through hour 36, one ready system at the end, `MTMF=1`, and zero failures, repair, PM, demand or backorders. The add SXO SHA-256 is `f6e696257675df485f9886dd58ee02d37645baa0941874211670b068bee9cb26`; exclude SXO SHA-256 is `0408531f5a3013da033eff9b939f7a11343b9edcecf56739863818ee4eaaa99b`.

The earlier local v1.0.0 diagnostic deployed both base and variant and showed that the scheduler chose the base; it is not a published result. The v1.0.1 runs prove variant operation, but their zero failure rates and default reports do **not** directly observe effective inherited item composition, item-level utilization/failure/repair aggregation, stock use, GUI rendering or cross-engine behavior. G03.var03 and var04 remain unpublished. A16 may reuse the accepted BSID source method as a bounded prerequisite, but must independently validate its distinct `CBSID` reconfiguration behavior.
