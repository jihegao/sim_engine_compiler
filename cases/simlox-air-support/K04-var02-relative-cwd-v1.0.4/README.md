# K04.var02 1.0.4 — relative MDB include and CLI process directory

This bounded Issue #18 case starts from the accepted [K04.var01 nested MDB case](../K04-var01-nested-mdb-include-v1.0.0/README.md). Its sole main-model change is the IncludeFiles path and comment: the first `INCFN` is the literal `level1.mdb`. The first MDB still points absolutely to a second MDB containing the BASE-01 Station row. The [contract](contract.json) freezes the sources, accepted parent, installed SIMLOX executable and manual, two process working directories, and run ID.

The guarded session-0 SSH runner uses `Global\SimloxIssue18NativeQueue`, preserves GUI PID 13340/session 1, temporarily maps the per-user MDB association to the installed 64-bit Access driver only for calculations, and restores the original value. It creates and independently reads back both Access MDBs, imports and exports one SXI, calculates that **same SXI path and bytes** once from its own directory and once from a separate process working directory without `level1.mdb`, and exports both reports. Native raw artifacts are retained locally under the ignored `runs/` directory and sealed by [closure.json](runs/k04-var02-relative-cwd-v104-ssh-20261004-01/closure.json).

Both runs logged the first include as the same absolute path under the SXI directory, followed by the second MDB, one IncludeFiles row and one Station row, with converter Errors 0, Warnings #108 and #126, Notes 0. The authored IncludeFiles comment, `Relative level1 at calculation working directory`, records the initial hypothesis and is **not** the accepted path explanation; the native logs falsified it. Both wrote usable SXO files. Their event logs and JSON reports match each other and the accepted K04.var01 parent byte for byte. Binary SXO hashes differ across calculations and are not an equality claim. The [author replay](author-native-validation-2026-10-04.json) checks 154 facts; independent replay and static review are in `review/`.

The earlier local candidates are excluded: v1.0.0 had a runner parameter error before import; v1.0.1 wrongly expected the alternate process directory to make the include fail; v1.0.2 relocated a byte-identical SXI to an MDB-free directory and logged resolution under that directory, then stalled on a missing-file interaction until its verified session-0 child was stopped; v1.0.3 ran cleanly but its contract incorrectly required binary SXO byte equality. Their closure hashes are recorded in the evidence index as diagnostics only.

This case establishes that changing the CLI process working directory alone did not change this relative top-level MDB include: SIMLOX resolved it under the SXI directory for these two calculations. It does not establish GUI file-dialog or MRU behavior, a general missing-file outcome, relative nested includes, SXI/OPI includes, arbitrary path handling, or full K04 coverage. Issue #18 remains open.
