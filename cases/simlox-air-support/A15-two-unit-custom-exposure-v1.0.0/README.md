# A15: custom KM exposure in two one-aircraft units

This bounded A15 case uses the accepted [J07 unit-owned mission model](../J07-unit-type-report-v1.0.0/cli-scope-signoff-2026-10-01.md) as its direct parent and the accepted [A15 custom-operation result](../A15-custom-operation-report-v1.0.0/cli-scope-signoff-2026-10-01.md) as the mechanism reference. The J07 parent supplies two aircraft, each in a different unit with its own fixed two-hour mission at 8–10. The [contract](contract.json) and [exact diff](exact-diff.json) freeze the only source changes: a custom `KM` OperationParameter, two MissionTypeUtilization rows and description. Both aircraft and missions remain distinct in the native log.

The two inputs swap rates: `a-hour-b-mission` gives MISSION-A 60 KM per hour and MISSION-B 120 KM per mission; `a-mission-b-hour` reverses them. [Build](build.py) verifies the accepted J07 parent SHA-256 and writes byte-stable inputs. Each input has 34 table schemas and 16 row-containing tables. The [native runner](run_native_ssh.ps1) performs guarded import, export, calculation, default report and [source roundtrip](check_roundtrip.py) through session-0 SSH under `Global\SimloxIssue18NativeQueue`, preserving the active GUI PID 13340/session 1. It creates immutable run directories under ignored `runs/`.

The installed default report omits SOACC. [Settings builder](make_report_settings.py) derives local `all`, `unit-a`, and `unit-b` report selectors from the fingerprinted installed `Default.sxs`. The operation flags use the same version-specific 12-byte descriptor-index workaround accepted in the earlier bounded A15 report; the installed settings file is never edited. [Report-only runner](report_existing_sxo_ssh.ps1) exports all three views from each sealed native SXO and fails on settings fallback. [Author replay](validate_native.py) verifies raw hashes, the native timeline, source rows, terminal state, exposure bins, horizons and all-unit = per-unit reconciliation. Independent read-only replay is under `review/`.

The local `.gitattributes` preserves the exact mixed-newline bytes of the native runner and roundtrip checker sealed in the run closures.

Both models completed two successful missions at 10, and both aircraft were ready at 36. Every unit selection reports `MissionOperationTotalAccumulated.SOACC=120` KM; the all-unit selection reports 240. Each per-unit cumulative half-hour bin reaches 30, 60, 90 and 120; all-unit bins reach 60, 120, 180 and 240. `MissionOperationTotal` averages those totals over the 36-hour simulation horizon, so it is a different measure from the accumulated total. The unit selector filters `MissionOperation` rows; `SystemResults` in those same exported reports retains all-unit labels and counts. [Evidence index](evidence-index.json) records all native and report-only run IDs and SHA-256 hashes. Raw SXI, SXO, JSON exports, logs and `.sxs` copies remain local under ignored `runs/`.

This supports two separate unit-owned fixed missions with one aircraft per unit. It does not disaggregate two aircraft in the same formation mission or establish UnitGroup rollup. Partial missions, failures, PM exposure, other seeds, physical kilometres, GUI rendering and cross-engine parity remain unverified.
