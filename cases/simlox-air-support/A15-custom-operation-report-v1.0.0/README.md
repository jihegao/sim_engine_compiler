# A15 custom operation: bounded report-only exposure

This package extends the accepted [A15 input pair](../A15-custom-utilization-v1.0.0/cli-scope-signoff-2026-09-30.md). It uses the same sealed native `.sxo` files from the per-hour and per-mission runs. No model is changed or recalculated. The accepted parent contract, input fingerprints, native import/export, event logs and GUI guard remain in that package.

The report question is narrow: does one complete 8–10 mission accrue equal native `KM` custom-operation exposure when configured as 60 per hour versus 120 per mission? The installed manual (SHA-256 `39427027c46809a9ce9ebcb9be04e7396d96746e42a6f8c7c0ba2ddc294ef8a3`, printed pp. 608–611) identifies `MissionOperation.SOACC` and its accumulated forms. `KM` is an abstract user operation label.

`make_report_settings.py` derives local `.sxs` copies from installed `Default.sxs` SHA-256 `1c2bb5380a2ac2e57fd3f0c782794154d331100c2bec2206d0caa430d3e21a5d`. The installed default is never edited. Its `MissionSettings` descriptor has 68 report flags, while its saved-value block has 64. Two length-extending probes were rejected by the native loader. A descriptor-default-only probe loaded but did not expose `MissionOperation`. The accepted local `operation-remapped-enabled.sxs` swaps the four operation descriptor indices with the four extendable mission indices and enables the corresponding saved flags. It preserves the file length, changes exactly 12 bytes and has SHA-256 `c2f9862c89f2aae0200d8f7a4f16a2e21b7c6ff896b42548c41b98e673f3f9b7`. This is a version-specific report settings workaround, not a general `.sxs` authoring API.

`report_existing_sxo_ssh.ps1` runs a report-only native export from each frozen `.sxo` through session-0 SSH under `Global\SimloxIssue18NativeQueue`. It checks the source, installed executable and default settings hashes and protects the active GUI PID 13340/session 1. A report fails if SIMLOX logs a settings fallback. Raw `.sxs`, reports, logs, invocation records and closures stay in ignored `runs/` with immutable run IDs. `validate_reports.py` checks closure hashes, settings evidence, four operation tables, `KM` bins, totals and pairwise equality. `review/` contains independent read-only replay.

Accepted report-only run IDs: `a15-soacc-hour-remapped-20261001-01` and `a15-soacc-mission-remapped-20261001-01`. Their closure SHA-256 values are `41d4879d81dfd7055df9535ba80210160b9813c2984866519d0c8e02eeed8b85` and `8efd5da23fccedadb723195506a0cc44d7dca8e0370261bb6fa99ac2a85e6d71`. Both reports show cumulative `KM` 30, 60, 90 and 120 across the four mission half-hours. `MissionOperationTotalAccumulated.SOACC` is 120 in both. `MissionOperationTotal.SOACC` is about 3.3333, the 120 units averaged across the 36-hour SIMPE period; it is not the mission total.

This package supports one system and one completed full mission. Partial-mission exposure, a two-aircraft per-system comparison, failure or PM consumption clocks, other seeds, GUI-only behavior, and cross-engine parity remain unverified. A15 as a whole stays open for those questions.
