## Prelaunch conditions and limits

The proposed child must change only `MaterielPM.PMINT` for `PMID=OP3` from 3 to 4; `OPID=OPHOURS`, `ATIM=DTIM=0`, missions, task, seed, and 60-hour horizon must remain fixed. Keeping `PMID=OP3` and `DESCR=Three-operation-hour service` is useful for the one-cell control but leaves a stale human-readable label. The child documentation and checker should explicitly state that PMINT=4 is authoritative; they must not describe the child as a three-hour PM.

The accepted parent `report-raw.json` contains a trailing comma and does not parse as strict JSON byte-for-byte. Preserve raw report bytes and normalize only an analysis copy before the required 120-row/11-field checks. This is a parser handling requirement for prelaunch, not evidence of a model defect. Full ledger assertions need to distinguish aggregate stock fields such as PNB from physical stock identity. A later independent prelaunch review must check the exact generated child input/diff, parser, acceptance logic, source pins, unique run path, protected GUI/session/mutex safeguards, and failure seals. A no-PM result would establish only this fixed three-hour exposure below a four-hour threshold, not the full before/at/over catalog panel or a general timing rule.
