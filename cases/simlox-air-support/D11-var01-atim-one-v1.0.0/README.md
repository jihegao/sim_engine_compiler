# D11.var01: ATIM=1 boundary

This bounded CLI case derives from the accepted [ATIM=0 D11.var01 control](../D11-var01-atim-control-v1.0.0/README.md). Only `MaterielPM.ATIM` changes from 0 to 1, plus a description. `PMINT=4` missions, the five fixed mission waves, one-hour `MS4` task, 60-hour horizon and seed remain fixed. The manual's integer front shift is `floor(1×4)=4` missions, making the boundary unusual.

An exploratory [probe contract](probe/contract.json) asked whether PM might start before the first mission or repeat without new mission use. Its guarded native run `d11-atim-one-probe-v100-ssh-20261001-01` showed first actual work at hour12 and repeated PM thereafter. The current [frozen contract](contract.json) recorded that exact timeline before a fresh guarded acceptance run `d11-atim-one-v100-ssh-20261001-02`; its event log and JSON report are byte-identical to the probe. The source, [exact parent diff](exact-diff.json), runner and [evidence index](evidence-index.json) bind the accepted run. Original SXI/SXO, logs and report remain local under ignored `runs/`.

The five missions succeed. Forty one `MS4` PM tasks start through hour60; forty complete, and the last begins at the horizon with no work time inside the result window. Four tasks pause immediately on creation for scheduled missions, before positive-duration subtask work, and resume after return. System/Stock bins integrate eight flight and 40 PM aircraft-hours; the last report bin has zero ready and one in PM, and the log starts another PM at the hour-60 boundary. These are observations for one schedule and seed, not a general ATIM=1 frequency law. Other intervals, PM interactions, GUI-only behavior and cross-engine equivalence remain unverified.
