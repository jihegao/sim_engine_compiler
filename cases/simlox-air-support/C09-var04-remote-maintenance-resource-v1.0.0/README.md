# C09.var04 remote resource for primary system maintenance

This three-arm teaching model derives from the published C03 two-aircraft shared-crew formation (`staffing-2`) and uses the published D01 direct system-repair row shape. Both aircraft fail during the one scheduled sortie in the fixed-seed run. The added `C09-DIRP` repair takes half an hour and requires one `P-MECH`. The local control allocates that resource at BASE-01. The remote arm allocates it only at BASE-02 and enables `ResourceRemoteSupport` with 0.25-hour outward and 0.5-hour return transit. The third arm keeps the remote route but sets `TaskResource.ENRMS=N`. `build.py`, `contract.json` and `exact-diff.json` fix the source, units and parent delta.

All three inputs completed guarded session-0 SSH import, export, calculation and report export with GUI PID 13340 preserved. Converter errors were zero; each run had the inherited ENLOG warning #108 and no-item warning #126, and the two route arms recorded notice #292 for the implicitly created receiving-station pool. The native import/export exactly retained 22 populated author tables in the local arm and 23 in each remote-route arm. Each run seals 12 raw artifacts in `evidence-index.json`; local `runs/` directories are ignored.

The first-replication event logs show two direct system failures at hour 8.53243 in every arm. Local `P-MECH` completes the repairs at 9.03243 and 9.53243 without transport. In the remote arm, one `P-MECH` travels BASE-02→BASE-01 from 8.53243 to 8.78243, serves two sequential repairs until 9.78243, then returns to BASE-02 at 10.2824. With `ENRMS=N`, no resource transport or repair completion occurs by hour 36, and both aircraft remain waiting for resources. Native SystemResults show two failures in all arms, two completed repairs and terminal ready count two in local and remote, and zero completions and terminal ready count zero in the disabled control. All reports have 72 half-hour bins; aggregate ResourceResults conserve `NR + NRRT ≈ NRN = 3` per bin, with 0.75 resource-hours in transit only in the remote arm.

The report aggregates resources across stations; the event log provides the station-level movement and final return. This fixed seed and one replication establish the observed direct primary system-repair borrowing and task-level disablement only. They do not establish general borrowing frequency, other support tasks, cost, performance, GUI visual behavior or cross-engine parity.
