# E10.var01: FIXED versus ONDEM downward spare transport, v1.0.1

This bounded SIMLOX 2017 CLI case derives from accepted [E04 FAST upstream transport](../E04-upstream-transport-fast-v1.0.0/cli-scope-signoff-2026-09-29.md), with accepted E02 local backorder as a supporting prerequisite. The two [frozen inputs](native-input-fixed.json) and [ONDEM input](native-input-ondem.json) bind the same depot-to-base link to `TransportPolicyProfile`: FIXED has one departure at h11; ONDEM is active h0–36. Both retain two-hour downward `TPTIM`, FAST demand forwarding, one opening depot spare, fixed upward transport, item repair and mission schedule. The [exact diff](exact-diff.json) pins the only changed fields.

The [v1.0.0 diagnostic](../E10-var01-fixed-ondem-v1.0.0/README.md) was NO-GO because its pre-run contract mistakenly required a resource report from a resource-free model. The [v1.0.1 contract](contract.json) corrects that requirement before fresh native runs and pins the earlier diagnostic closures. Native output remains in ignored `runs/`; the [author](validate_native.py) and separate `review/` checker replay the raw evidence. The [signoff](cli-scope-signoff-2026-10-03.md) records the exact observed scope.

Under the one frozen seed, both arms fail the same LRU at h9.8829 and demand the depot spare at h10. ONDEM ships that physical spare at h10 and receives it at h12; FIXED queues it until h11 and receives it at h13. Backorder duration and aircraft readiness each differ by one hour. This does not test a second demand, repeated departures, batch size, nested profiles, time distributions, GUI behavior or another engine.
