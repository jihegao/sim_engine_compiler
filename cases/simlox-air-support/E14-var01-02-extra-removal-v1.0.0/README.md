# E14: serial extra SRU removals and no-fault-found repair

This bounded native CLI case uses one aircraft, one repaired LRU and two traditional SRU positions at BASE-01. The [contract](contract.json) froze seeds 2–6 before execution. Each seed has a `RRF=1,NFFF=1` control and a joint `RRF=4,NFFF=2` arm; both use `NFFT=0.25`. The [builder](build.py) verifies ten deterministic input files against the accepted G01 parent. It also enables `Item.TRACK` and half-hour ITEM result collection through h36 for the LRU and both SRUs.

Run `build.py` without `--write` to check the frozen inputs. The guarded [native runner](run_native_ssh.ps1) performs import, export, calculation and default report export for each arm under session-0 SSH. The guarded [selected report runner](run_item_reports_ssh.ps1) reopens the sealed SXOs to export BASE-01 `ItemResults` for all three items. Both use the host-wide native mutex and preserve the protected GUI PID 13340. The [author validator](validate.py) replays source, closure, event and report checks; the [independent checker](review/independent_replay.py) does its own read-only replay. The [evidence index](evidence-index.json) seals the local raw artifacts, which stay under ignored `runs/`.

The five extra arms produced 15 actual extra removals and six NFF repairs; controls produced none. All selected item demand and stock ledgers reconcile with the event logs. One NFF repair was still active at h36. The [signoff](cli-scope-signoff-2026-10-05.md) gives the fixed-seed results and limits. Because RRF and NFFF change together, this case records their joint behavior and does not isolate either parameter's individual effect.
