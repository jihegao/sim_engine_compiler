# G06.var04 fixed-mission online-repair counterexample

This bounded fixed-seed pair tests `RBDParallel.ONLM` under an ordinary fixed mission. The accepted [G05.var04 continuous online arm](../G05-unavailable-standby-v1.0.3/README.md) supplies the source topology. `build.py` changes the mission pattern to the fixed default and restores the accepted fixed-model travel fractions `TFOUT=TFRET=0.25` of the 26-hour duration. The two new fixed arms differ only in `ONLM=Y/N` and the problem description. Both retain the same passive B/A/C priority, 0.5-hour switchover, B 40-hour and A 0.5-hour direct system CM, seed, schedule, and zero-demand stock rows.

Both guarded native runs roundtrip all 23 populated input tables exactly and convert with zero errors. Their byte-identical event logs show B and A failing at h8.94145 and h17.5636, mission success/completion at h34, both CM tasks starting at return h34, A repair completing h34.5, and B still under repair at horizon36. Every ResultSummary cell and every cell of the 72 System and 72 Stock rows match across fixed Y/N. The accepted continuous Y parent instead starts B/A CM at their faults and completes A repair h18.0636. Its `NREPT` report marker is [18,18.5), versus [34.5,35) for both fixed arms; continuous and fixed summary `MSTF/MSUF` also differ and are reported by pattern, not merged into one success claim.

The [contract](contract.json), [exact source diffs](exact-diff.json), [CLI sign-off](cli-scope-signoff-2026-10-02.md), and [evidence index](evidence-index.json) bind this result.
