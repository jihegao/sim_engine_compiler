# K02.var01: named Station JSON exchange (v1.0.1)

This bounded CLI case derives from accepted [K01.var04](../K01-var04-parent-child-model-diff-v1.0.0/cli-scope-signoff-2026-10-04.md) (input SHA `d1ff80f7e0de8259b6f38b6373c7ad4797d897e17c4397a7060dfbefbeb851dc`). K01 supplies the accepted three-hour mission model and CLI-visible source lineage; its GUI views and templates remain unverified. The K02 [contract](contract.json) and [exact diff](exact-diff.json) were frozen before fresh guarded runs. The installed SIMLOX 2017 manual, physical pages 152–154 and 167–168, describes the JSON model/table/column/instance structure, null cells and native `-jimport`/`-jexport` commands. Manual SHA-256: `39427027c46809a9ce9ebcb9be04e7396d96746e42a6f8c7c0ba2ddc294ef8a3`.

The accepted `named` input changes only the description and Station structure: the BASE-01 row moves to explicitly named instance K02-BASE, and unused station K02-NAMED appears in a second explicit instance K02-AUX. Native export preserves both authored instance names, typed columns, keys, row order, null cells and the existing `OperationProfile.DTIM` binary64 value `0.3333333333333333`. It also adds exactly one empty default Station instance with one all-null 21-cell row. This native canonicalization is included in the frozen v1.0.1 gate; no other authored row changes. The converter reports Errors 0, Warnings #108/#126, Notes 0. Native mission log is byte-identical to K01; ResultSummary and all 72 System and Stock half-hour rows match K01, with only ProblemDescription differing.

The separately gated `inactive2` input retains BASE-01 and appends unused K02-INACTIVE with `Station.inactive_rows=[2]`. Native conversion and the parent mission/report pass, but export blanks that second row and omits `inactive_rows`. Its roundtrip gate therefore fails and it is an excluded diagnostic. The earlier [v1.0.0 diagnostics](../K02-var01-json-structure-v1.0.0/README.md) show `[1]` blanking BASE-01 and a strict named-instance topology failure. These four raw runs are preserved under ignored versioned `runs/` directories; the [evidence index](evidence-index.json) records IDs, paths and SHA-256 seals. The [author replay](author-native-validation-2026-10-04.json), [independent replay](review/independent_replay.py) and [sign-off](cli-scope-signoff-2026-10-04.md) state the accepted and excluded scopes.

This publication establishes one installed-engine CLI JSON behavior for two named Station instances, nulls, declared types and this source's binary64 double value. It does not establish lossless inactive-row exchange, general multi-instance behavior, GUI import/export views, SXT templates, larger precision values, cross-engine equivalence, full K02 completion or automatic K04–K07 prerequisite clearance.
