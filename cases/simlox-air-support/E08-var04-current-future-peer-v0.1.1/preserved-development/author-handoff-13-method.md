# Author read-only replay method

This is a retrospective classification of two already sealed direct E08 runs. `replay.py` checks the accepted source, raw, closure, invocation and selector byte pins before comparing reports. It reads native JSON with quote-aware trailing-comma removal on an in-memory copy; sealed files are not rewritten. Expected cells come from the two source models and typed physical event edges, not from the candidate report cells. The two direct runs each contribute one default report and three station reports: 24,342 cells per arm, 48,684 total.

The source comparison fixes `ENLAT=Y`, `DLAYL=N`, `LTMOD=IMMEDIATE` and the common schedules. The differing inputs are the description, BASE-02 starting stock 1 versus 0, and the one future DEPOT-01 to BASE-02 transfer (h9, quantity 1, duration 2). The replay binds physical item IDs, transport task/request IDs, route origin and destination, quantity, arrival and subsequent repair or fit. It checks all column and instance metadata, nulls, row order, source-count and whole-bin fields exactly. Fractional metrics use only the contract's printed-edge half-last-decimal propagation and ceilings; an unknown or excessive bound fails.

For stock demand fields, the installed manual's ROS definition is a fraction of demands not immediately served (physical pp. 730–732); a no-demand interval is null. At BASE-02 h10 in the current arm there is one logged typed demand, an immediate take of physical ID1 and no backorder or wait interval. This gives ROS and ROST zero and WT/WTT zero. Native `WTS` is null for that no-wait demand; the replay treats that as a bounded native presentation convention for these sealed runs, without asserting a general WTS law. It rejects both a changed ROS null and a changed WTS zero in that bin. Demand/wait events, rather than candidate report cells, select the branch.

The first development parser expected blank `instance_name` for every default report. The sealed default SystemResults and StockTotalResults use their aggregate interval names, while the selected station instances are blank. These are exact report metadata strings, with no effect on the numerical oracle.

`self_check.py` verifies the original seals and all 48,684 report cells, then injects in-memory changes into production comparison and event gates. Its thirteen rejected mutations cover zero/count/null/description/metadata, peer item ID, transport destination/quantity/request, the immediate-demand ROS and WTS states, and the source stock delta. These fixtures are semantic gate tests, not native behavior evidence.

Development-only failed drafts and their captured stdout/stderr are in `preserved-development/`. The first four failures were authored parser/oracle mistakes: placeholder table handling, selection of a later arrival instead of the first arrival, default report instance names, and no-wait stock field representation. The eighth draft's failed route check conflated arrival of an item needing depot repair with its later repaired-stock arrival. These failures were not native failures or accepted results; each available exact failed source and output was saved before correction. Successful draft snapshots are retained separately.
