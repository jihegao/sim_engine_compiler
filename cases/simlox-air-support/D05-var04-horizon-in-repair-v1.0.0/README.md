# D05.var04 hour-26 horizon during direct repair, v1.0.0

This bounded variant demonstrates a native run stopping while a positive-capacity worker is performing critical direct repair. It covers the **in repair** part of the catalog's “horizon in repair / awaiting repair” boundary. The accepted [D05 one-worker case](../D05-maintenance-competition-v1.0.0/cli-scope-signoff-2026-09-30.md) is the direct parent; its input SHA-256 is `4443d057ade36010a84186aa0f9ac8279886563db190ed80699b7fe48ad2baad`.

The [frozen input](native-input.json) changes the simulation and all result-window ends from hour 36 to 26, removes the parent’s third mission scheduled at hour 32, and changes only a description label. The [exact parent diff](parent-diff.json) identifies four changed tables and 27 unchanged tables. The repair, PM, worker capacity, first two missions, random seed and failure rate are retained. The [contract](contract.json) records the hypothesis before native acceptance.

The accepted native run is `d05-var04-horizon-v100-ssh-20260930-02` in ignored local `runs/`. Session-0 SSH, the host-wide SIMLOX queue and GUI PID 13340 identity guard were used. Import, export, calculation, report, and source-table roundtrip completed. Conversion had zero errors and the documented #108 logging and #126 item-free system warnings. The source’s 22 row-containing tables matched the native export; native-added all-null default tables do not change the source rows.

The first mission succeeds at 10. The second mission starts at 20, suffers a critical failure at 22.6835 and aborts. Repair work books the sole worker at 23 for a planned five hours. Both CAL24 PM task objects start at 24; the healthy aircraft's PM worker request fails, and the faulted aircraft's PM remains behind its repair. At the hour-26 stop, the last report bin still shows one aircraft in repair and one worker in use. No repair/PM completion or worker deallocation event occurs before the stop. The report integrates three aircraft-hours of repair, three worker-hours of use, and approximately two worker-request waiting hours. `ResourceResults.NRA=1` is not interpreted as free capacity here because the same bins show `NRUM=1` and the log records the active booking.

It is excluded from acceptance; its raw files remain under ignored `runs/`.
