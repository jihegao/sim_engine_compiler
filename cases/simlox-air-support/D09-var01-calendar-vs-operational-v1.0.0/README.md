# D09.var01: calendar versus operational noncritical fault tolerance

This accepted bounded native CLI case derives a matched pair from [D08.var03](../D08-var03-criticality-v1.0.0/cli-scope-signoff-2026-10-02.md): one aircraft with a traditional LRU that fails noncritically during the first mission. Both children set `Item.NCFTL=0.2` hours and local nominal spare stock to zero, following the accepted [E02 zero-stock precedent](../E02-zero-stock-local-backorder-v1.0.0/cli-scope-signoff-2026-09-29.md). The [calendar input](native-input-calendar.json) uses `Item.NCFTT=CALENDAR`; the [operational input](native-input-operational.json) uses `Item.NCFTT=OPERATION`. Their only business difference is the clock type; the descriptions also differ. The [pre-run contract](contract.json) and [exact diff](exact-diff.json) freeze these sources.

Both guarded native CLI runs completed; [author replay](author-validation.json) passed 76/76 checks and [independent read-only replay](independent-verdict.json) passed 1,640/1,640. Both finish the first mission with a noncritical fault and a pending replacement-item backorder. Calendar tolerance expires while idle at h10.0829; operational tolerance expires during the second mission at h20.0829 and aborts it. Critical escalation starts physical removal and same-item repair, clears the backorder, and restores aircraft readiness. The [signoff](cli-scope-signoff-2026-10-02.md) details the event and report reconciliation and limits. Raw native artifacts remain under ignored local `runs/` and are sealed in the [evidence index](evidence-index.json).

The installed dictionary calls the operational choice `OPERATION`; the manual prose calls the mode “operational.” The pair tests one seed, one 0.2-hour threshold and a zero-spare waiting path. Other thresholds, active maintenance, number limits, resource contention, GUI-only behavior and cross-engine parity remain open.
