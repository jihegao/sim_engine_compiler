# A05 continuous mission baseline and initial shortage

This three-run group derives from the accepted [A03 two-aircraft formation](../A03-two-aircraft-formation-v1.0.1/cli-scope-signoff-2026-09-29.md). The fixed control extends its mission duration from two to four hours. The continuous control sets `MissionType.MPAT=CONTINUOUS` and clears `TFOUT`/`TFRET`; a [sealed v1.0.0 probe](../A05-continuous-baseline-v1.0.0/README.md) established that the native converter rejects those travel fractions for continuous missions with error #335. The third input changes only the continuous deployment from two aircraft to one, retaining `NOS=MNOS=2`. The [contract](contract.json) and [exact diffs](exact-diffs.json) were frozen before the v1.0.1 native runs.

The guarded session-0 SSH runner completed all four CLI steps and exact source roundtrip for each input. Both two-aircraft controls start at hour 8 and finish at hour 12, with both aircraft returning ready and eight aircraft-hours of mission operation. The one-aircraft continuous mission starts and suspends at hour 8. Its retained aircraft is reported suspended, with zero mission operation in every half-hour bin from 8 to 12; the log emits a `mission resumed` marker only at the hour-12 completion instant. The report's `MSTF`/`MSUF` values are 1 in the fixed control and 0 in both continuous runs, despite the continuous logs' `mission success` event. The installed SIMLOX manual (physical PDF pages 551–553, 558–559) defines these summary fractions over fixed missions and excludes continuous missions, so zero here is consistent with the documented denominator rather than an operating-success measure for the continuous inputs.
