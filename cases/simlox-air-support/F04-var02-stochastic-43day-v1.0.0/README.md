# F04.var02: 43-day stochastic risk fleet

This bounded case extends accepted F04.var01's eight-aircraft, two-base, 1032-hour deterministic regression. The five BASE-01 and three BASE-02 aircraft, 21 requests of each mission wave at 48-hour spacing, preventive maintenance, stocks, crews, transport and result interval remain fixed. The [input](native-input.json) changes seven parent cells: description; NREPS from 1 to 128; TCLEV from inherited null to explicit 0; System, LRU and SRU failure rates from zero to 1,000,000 per million operating hours; and RISK-MISSION.MFF from zero to one. A two-row System replication control requests TOTAL for both units, with TIME and SNAPS disabled. The [exact diff](exact-diff.json) and [contract](contract.json) freeze the source and metric gates.

One excluded single-replication pilot confirmed a risk fault, aborted mission, LRU backorder, depot stock issue, transport, maintainer allocation and repair path. An excluded 32-replication variance pilot validated the two-unit TOTAL selector and first-replication report semantics. Its analysis projected that a separately frozen 128-replication run could meet the predeclared half-widths; neither pilot is acceptance evidence for stochastic precision.

Two fresh serial session-0 SSH native runs passed import/export, calculation, default report, report-only OUTRP replication export and exact roundtrip of 31 authored populated tables. Each had converter Errors 0, Warnings 1 (#108 log-volume notice), Notes 0, and a local raw SHA closure of 14 files. Their first-replication event logs are byte-identical to the one-replication pilot: 63 mission starts, 43 successes, 20 risk aborts and 27 critical random failures. The per-replication reports contain 128 unique seeds and 128 System TOTAL rows for each base. The first replication has FMSUC 43/63 and NFAIL 27; the mean of the per-replication values reconciles with the default aggregate report. Both event logs and both raw reports are byte-identical across the same-input repeat runs.

Nominal two-sided 95% Student t intervals are calculated from the 128 per-replication values, not from the native ResultSummary RSM fields. Mean mission success fraction is 0.67250 with half-width 0.00177 (absolute target 0.05). Mean aircraft operating time is 158.807 hours per 43-day replication with half-width 0.930 hours (relative target 5%). Mean observed failures are 25.906 per replication with half-width 0.403 (relative target 10%). All three predeclared thresholds pass. The 2,064 half-hour aggregate bins give descriptive averages of 51.8125 backordered item-hours, 389.296 booked resource-hours and 30.336 queued resource-hours per replication; no per-replication precision is claimed for those support measures. The aggregate terminal bin has seven ready aircraft and one unavailable on average.

The [author replay](author-native-validation-2026-10-04.json) checks both local closures, source pins, roundtrips, report table identities, first-replication event counts, aggregate arithmetic, confidence calculations and repeatability. The native default report has a trailing comma, so the replay uses a narrow parser correction while preserving its raw bytes; the separate OUTRP report parses as strict JSON. Bulky native outputs remain in ignored local run directories. A separately reviewed [evidence index](evidence-index.json) seals their hashes.

## Reproduce and scope

Run build.py and describe_diff.py to verify the frozen source. From a session-0 SSH shell, run run_native_ssh.ps1 with Arm repeat_a or repeat_b and a fresh RunId, serially. It enforces sshd ancestry, the host-wide native mutex, active GUI PID13340, source and tool fingerprints, reviewed diagnostics, roundtrip and closure. Run validate_native.py after both runs.

This is one installed SIMLOX CLI engine and one model family. The 128 configured pseudo-random replications support the stated nominal precision checks, not a proof of seed independence or a general population law. Two same-seed executions test repeatability, not 256 independent samples. ENLOG exposes only the first replication's event timeline. Stock and resource results are descriptive aggregate measures. GUI visual parity, cross-engine equivalence, later F04 support contrasts and Issue #18 remain open.
