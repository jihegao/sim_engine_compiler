This bounded pair derives from the accepted [E01 local-spare model](../E01-local-spare-explicit-replacement-v1.0.0/README.md). The quiet control changes only the system and item random-failure rates to zero and its description. The accepted [H02 system-damage source](../H02-var01-system-damage-direct-repair-v1.0.0/README.md) supplies hash-pinned table schemas only. Both arms retain one aircraft, one mounted LRU, one local spare, three fixed two-hour missions, seed1 and horizon36.

Two serial guarded session-0 SSH runs exactly roundtrip 20/24 authored row tables, convert with zero errors, and preserve GUI PID13340. The quiet control completes all three missions. The child logs item-identified in-flight BATTLE-HIT at h8.78145, h20.7434 and h32.3406, aborting each mission. After return, physical spare IDs 0/1/2 are issued from `BASE-01` and the system's explicit ten-minute remove plus twenty-minute fit task completes. The system becomes ready at h9.78145, h21.7434 and h33.1812, before the later scheduled launches. Damaged LRU IDs 1/2/3 each receive one hour of local direct item repair and return to stock at h10.4481, h22.4101 and h33.8479. The model log shows stock dropping from one to zero at issue and returning to one after repair.

Each run has 72 aligned half-hour System and Stock bins. The child has three `NDAM`, three `NREPT` and three `NDD` markers, zero lost-aircraft hours and terminal ready1. Its Stock report `PNB=1` is a nominal count across bins; the physical issue and stock-return sequence comes from the model log. This one-seed configuration covers primary LRU damage with `REPF=1` and explicit damage replacement. The ordinary E01 replacement path has the same task and duration, so this pair does not isolate which data source won a fallback priority. It does not test `REPF=0` or an intermediate value, already-failed items, multiple damage consequences, shortages, GUI visual behavior or cross-engine parity.
