# G11.var01: fixed initial ages on three aircraft

This package derives two matched three-aircraft inputs from accepted [D03 calendar PM](../D03-calendar-pm-v1.0.0/cli-scope-signoff-2026-09-30.md). Both use one `CAL100` system PM, a 104-hour horizon, the same three scheduled missions and seed 1. The control has no prelife. The fixed-age arm adds `Prelife(PL-SYS, TEACH-AIR-01)`, three `PrelifeData` individuals with `CALHOURS` ages 0, 60 and 120, and the deployment's `PLID`. [The contract](contract.json) froze the expected first PM starts before native execution; [the exact table diff](exact-diff.json) records all authored changes.

The guarded native Prelife Log lists `AGE0`, `AGE60` and `AGE120` with their ages. The control's three aircraft first start `CAL100` at hour 100. In the fixed-age arm, native entity 1 starts at hour 40, entity 2 at hour 80 and entity 0 at hour 100. This matches a 100-hour cycle: age 120 rolls to the next multiple of 100, leaving 80 hours. The Prelife Log lists PLINDs but no numeric simulation IDs; the ID association follows input order and matching first PM times.

`build.py` and `describe_diff.py` verify frozen source. `run_native_ssh.ps1` guards loopback SSH session 0, `sshd.exe` ancestry, the host mutex, active GUI PID 13340 and pinned parent/product/manual/dictionary bytes. It enables the user's Prelife Log option only around the hidden native calculation and restores the original `NO` value in `finally`. `validate_native.py` and a separate reviewer's `independent_replay.py` replay local raw files without launching SIMLOX. Native raw files stay in ignored `runs/`; [evidence-index.json](evidence-index.json) publishes their hashes. The [scope sign-off](cli-scope-signoff-2026-10-02.md) limits this to fixed top-level system calendar ages and first PM timing.
