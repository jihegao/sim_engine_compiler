# A14.var06 repeated profile dependence (v1.0.1)

This bounded native CLI case compares one `MissionDependenceProfile` row with two explicit `MissionDependence` rows over two A09-style hierarchical waves. Both waves have concurrent SUPPORT and EXECUTE continuous missions. The [frozen contract](contract.json) and [exact diff](exact-diff.json) identify the accepted A14.var01 parent and A09 profile donor, source fingerprints, model configuration and predictions before three fresh native runs.

The root `BASIC-SCHEDULE` repeats subprofile `A14-WAVE` twice with `IQTY=2, IPER=48`; the child SUPPORT and EXECUTE rows each have `IQTY=1, STIM=8`. Native starts occur at 8 and 32. SUPPORT succeeds at 10 and 34. With no dependency, EXECUTE succeeds at 12 and 36. Both the explicit and profile dependency forms abort EXECUTE at 10 and 34. Their full native event logs are byte-identical, and all non-description report tables match. Each run has 80 half-hour System and Stock bins through hour 40; terminal readiness is two aircraft.

The inherited [v1.0.0 diagnostic](../A14-profile-repeated-v1.0.0/README.md) had only 32 System bins because its MISSION/SYSTEM `ResultCollection` overrides ended at hour 16. It failed its frozen contract and remains unpublished. v1.0.1 extends those two source windows to 40 before new runs. The [case sign-off](cli-scope-signoff-2026-10-01.md) records immutable run IDs, native closure hashes, 1,938 author checks and 13,626 independent read-only checks.

Original native artifacts remain in ignored local `runs/` paths. To reproduce on the licensed 4700-3 host, run `build.py` and `describe_diff.py` as source checks, execute `run_native_ssh.ps1` via authenticated session-0 SSH with fresh RunIds for all three variants, then run `validate.py`. Original run IDs cannot be reused. This tests only a two-level, two-wave, IQTY=1-leaf configuration. IQTY>1 leaves, deeper profiles, overlaps, other dependency types, GUI visual content and cross-engine equivalence remain unverified. Issue #18 stays open.
