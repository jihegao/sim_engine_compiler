# B03.var01 v0.1.2 read-only full-report method

The accepted B03 v1.0.2 `-02` run is the only positive native evidence. Failed `-01` remains diagnostic. The parent already published the explicit COLD-FIRST and later HOT-SORTIE physical path; this case audits 4,044 report cells retrospectively, with zero new native calls.

`replay.py` checks its frozen contract and independent contract GO, distinct local and base-Git identities of 38 parent/dependency source files, installed executable/manual/dictionary, both B03 raw run closures and their files, the original owner receipt, all 48 frozen v0.1.1 files and root probe receipts through inert copies, and the accepted B02 report format byte pin. The archived publication index is checked against its base Git blob. A later live index may add entries only after preserving the archived prefix and metadata. No missing raw file is replaced by synthetic output or an arbitrary fallback.

The quote-aware parser removes trailing commas only outside strings. The roundtrip gate compares all 31 model tables, complete table and instance metadata, their 14 populated row sets, and all-null empty-table placeholders. Control fixes one replication, 36 h horizon, half-hour bins and no PM. The source fixes one FRT=0 aircraft, no item/resource/fault/repair/PM mechanism rows, explicit cold and hot MTIDs, three launch profiles, the preparation task route and breakdown durations. The typed log gate accounts for every one of 121 timed lines with exact full-line grammar and category cardinalities, then links the three missions, four subtasks and one physical aircraft through preparation, work, flight, turnround, ready and terminal events in line order. It rejects extra fault, item or resource events, shifted generic diagnostics, different identifiers, wrong work duration and unknown lines. A source work annotation with overly coarse printed precision fails before value comparison.

Seven state integrals are calculated from source-scheduled edges after matching their typed events: unassigned ready NSYRY 27 h; assigned preparation NSYMP 5/6 h; assigned prepared waiting NSYMR 13/6 h; operation NSYMO 6 h; assigned sum NSYMA 9 h; one-aircraft NSYA 36 h; and FTMO operation exposure 6 h. Each integral is checked against the frozen contract independently. Each half-hour row uses interval overlap from those intervals; STACC comes from the active mission, and NPSTA/NPSUC count linked preparation starts and completions. The report itself is read only at the final comparison gate.

All 40 SystemResults columns have explicit classes. Twenty zero-valued state/counter fields are justified by the pinned empty mechanism tables and absence of corresponding typed events: no reconfiguration, maintenance transport, mission suspension, fault, repair, PM, item/resource wait, loss, damage, repeat, switching or completed downtime. SYDT is null with no completed downtime period (manual physical pp645–646). Five other fields—NSYAL, STREQ, STF, STLOW, SYDTU—are **exact zero native presentation gates** for this bounded one-aircraft profile, 360 cells in total. Manual pp633–634,567–571,645–646 defines percentile and System Time concepts, but supplies no source/event formula yielding those zeros; accepted B02 report bytes corroborate the format in ready and flying bins. The method makes no statistical-correctness or general zero-law claim for these five fields. The remaining System keys, states, counts and FTMO have source/event formulas; any unclassified column fails.

The summary comes from three source-selected successful missions over h0–36. ProblemDescription comes from the source PDESC. With no item/stock position or typed demand, StockTotalResults has NBO and demand counts zero, PNB one and NBOU/ROS/ROST/WT/WTT/WTS null on all 72 rows. Manual pp729–732 explains the demand-conditioned measures. Empty-universe PNB and null NBOU/WTS are explicit bounded native presentation conventions, not general stock laws.

The checker compares table/root/instance key sets, exact column dictionaries, names, order, rows, IDs, nulls and all 4,044 cells. Zero, whole-bin, integer, metadata and presentation values have zero tolerance. Only genuinely fractional hot preparation/wait cells get a bound from the matched printed event token: half its last decimal unit divided by 0.5 h plus at most 5e-7 serialization. The bound must be at most 1.1e-4. A missing formula, edge or excessive uncertainty is NO_GO; the checker never chooses a rule from candidate values.

Use the bundled Python read-only: `python -X utf8 -B replay.py` and `python -X utf8 -B self_check.py`. Both print deterministic JSON by default. Replay `--output` creates only a new named path. Self-check verifies original seals before in-memory source, log, report and metadata mutations; it does not change raw. This v0.1.2 method does not import old parent or independent review scripts.
