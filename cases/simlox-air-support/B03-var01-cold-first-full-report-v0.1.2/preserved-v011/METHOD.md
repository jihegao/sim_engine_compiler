# Read-only full-report method

The accepted B03 v1.0.2 `-02` input and sealed raw run are the only positive native evidence. The failed `-01` run is checked for custody and excluded from acceptance. The published B03 package already covers the physical cold-first and later hot-sortie path; this method adds a complete, source/event-derived audit of its report.

`replay.py` checks the v0.1.1 contract, independent contract-GO memo, 38 B03/B02/A02 source files against distinct local and base-Git byte identities, the installed executable/manual/dictionary, two raw closures and their 22 files, the excluded v0.1.0 byte copies, and the original owner receipt. It compares the archived publication-index snapshot to the base Git blob and requires the current index to retain the original entries and metadata as a prefix. Only those two explicitly named context files have archival copies; raw run files have no generic fallback.

The quote-aware parser removes native trailing commas only outside JSON strings. The roundtrip gate compares all 31 source tables, their complete column metadata and instance names, 14 populated table row sets, and the exact all-null placeholder shape of otherwise empty tables. Source rows determine three explicit MTIDs/launches, the preparation task route, the 10+20-minute cold breakdown and the one-step 10-minute hot breakdown. Typed `model.log` events must bind the same aircraft and mission IDs to preparation, ordered subtasks, launch, success, return and ready state. Equal-time physical line order and global event cardinality are checked.

The expected SystemResults rows are calculated over each half-hour interval from one physical aircraft's source and event state intervals. `NSYRY` is unassigned ready (27 h), `NSYMP` preparation (5/6 h), `NSYMR` assigned and prepared waiting (13/6 h), `NSYMO` mission operation (6 h), `NSYMA` their assigned sum (9 h), and `NSYA` one aircraft throughout (36 h). `FTMO` equals operation occupancy for this one-aircraft source. `STACC` follows active mission occupancy; `NPSTA` and `NPSUC` count typed preparation starts and completions in their actual half-hour bins. Other System fields are zero except `SYDT`, which is null. Manual physical pages 629–643 distinguish these states.

Summary values follow three scheduled successful missions and the fixed h0–36 collection window. The input's ProblemDescription supplies `PDESC`. With no item/stock positions, typed demands or backorders, the contract predeclares StockTotalResults `NBO=0`, `PNB=1`, zero demand counters and null `NBOU/ROS/ROST/WT/WTT/WTS` for each of 72 rows. Manual pages 729–732 support demand-conditioned risk/wait values; empty-aggregate `PNB` and undefined `NBOU/WTS` are bounded presentation conventions of this accepted profile, not general SIMLOX laws.

All four native report tables, exact column metadata and instance names, 4,044 expected cells, nulls and row order are checked. Strings, IDs, counters, source constants, zero and whole-bin values are exact. Only genuine fractional hot preparation/wait occupancies use the predeclared bound: half of the last printed decimal unit of the matching typed event time, divided by 0.5 h, plus at most 5e-7 for native serialization. The bound must not exceed 1.1e-4. A missing formula or event link is NO_GO. The expected rows are constructed without reading native report values.

Use bundled Python read-only: `python -X utf8 -B replay.py` and `python -X utf8 -B self_check.py`. Both print deterministic JSON by default and do not write an existing verdict. The optional replay `--output` uses exclusive creation of a **new** output path. `self_check.py` first verifies the untouched seals, then injects in-memory semantic mutations into the production parsing, event and report gates. No old reviewer/build/native script is invoked.
