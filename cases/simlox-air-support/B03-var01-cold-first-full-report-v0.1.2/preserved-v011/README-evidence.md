# B03.var01 retrospective cold-first report audit

The accepted B03 v1.0.2 CLI run already published the explicit `COLD-FIRST` first sortie and two later `HOT-SORTIE` sorties. This v0.1.1 package adds a bounded, independent **full 4,044-cell report audit** and catalog variant traceability. It creates no native run and claims no new physical behavior.

The first sortie allocates `<TEACH-AIR-01,0>` at h7, performs INSPECT for 10 minutes followed by SERVICE for 20 minutes, waits prepared until its h8 launch, and succeeds/returns h10. Explicit hot missions prepare at h11 and h15 using one 10-minute HOT-SERVICE step, then fly h12–14 and h16–18. The same aircraft remains ready at h36. The source delta from B02 changes six coupled tables, so this is not an isolated cold-only causal comparison. An automatic recipe switch driven by sortie count, history or thermal state remains unverified.

The read-only author replay checks the frozen B03/B02/A02 source and local versus published Git identities, installed SIMLOX/manual/dictionary pins, accepted `-02` and excluded failed `-01` raw closures, invocation context, 31-table import/export topology and all 4,044 report cells. The independent replay verifies the same bounded report result separately. The `-01` author validator failure remains excluded even though its model log and report bytes match `-02`; its recorded validator SHA is not represented as recovered source bytes. Historical v0.1.0 contract and its NO_GO are preserved byte-for-byte.

System results are derived from source and typed events: `NSYRY` 27 unassigned ready hours, `NSYMR` 13/6 assigned prepared-waiting hours, `NSYMP` 5/6 preparation hours, `NSYMO` 6 mission-operation hours, `NSYMA` 9 assigned hours and `NSYA` 36 aircraft hours. The four report tables contain 1, 11, 2,880 and 1,152 cells respectively. Nulls, identities, counts, zero and whole-bin cells are exact; genuinely fractional hot-preparation cells use the contract's printed-time bound fixed before replay. Empty-stock `PNB=1` and null demand-conditioned ratios are bounded to this accepted native presentation, not asserted as a universal SIMLOX law.

The [reproduction guide](REPRODUCTION.md) gives read-only commands and raw retrieval requirements. The [evidence index](evidence-index.json) records source, raw, old-failure and context byte identities. The authoritative publication state is the repository's `../publication-index-v1.json`; this guide records the bounded content result and does not assert that the root catalog/PR gates have completed.

Limits: one item-free, resource-free teaching aircraft, fixed source schedules and one accepted CLI run; no GUI-specific behavior, cross-engine equivalence, performance, automatic cold/hot switching, general report-law claim, whole B03.var01 coverage or Issue #18 completion.
