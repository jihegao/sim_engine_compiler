# Independent frozen-bundle gate: NO_GO_STATIC

This decision supersedes and withdraws my preliminary `GO_PURE_PREFLIGHT` note, which is retained unchanged as historical review evidence at SHA-256 `1d8cd4966524155db5f94eb5ebc4dc09e72828ae00987458e46623bb299fd692`. Do not run even the actual SSH PowerShell preflight against this frozen bundle, issue an approval JSON, or launch SIMLOX. No v1.0.1 native child or run directory existed when this defect was identified.

The rejected exact bytes are prelaunch manifest SHA-256 `fce232eff4e21f6f1dbb065e4f36bc166f1871f94dc97fe2cd7c3bbce671c4bb` (67 source pins), validator SHA-256 `fa9b0dd2f8d2fc12b88275abbb523c95b43eaddf6b831fb693956a4b617ea2da`, runner SHA-256 `5294e312c83bb659dcac59200ded97039263a2c8fed7d8590d4cdb24deddda6b`, and unchanged contract SHA-256 `cc3aa75b3c4f6cec8fff57c0de28abf9ed552f4c0bc836e581295856ca30f283`.

The validator checks stock take and return counts and a bounded terminal count. It does not bind the opening physical item IDs to each A/B reconfiguration demand, stock take, fit/removal task and return edge. A trace with the right counts and report aggregates but wrong physical item attribution could pass. That is material for the contract's physical stock conservation and source-bound A/B contrast. The current per-cell StockTotalResults oracle cannot repair the omission because aggregate bins do not identify the physical items.

Recovery requires preserving this manifest and validator as excluded static drafts, then a separately frozen validator that checks each observed item ID and event edge against the opening stock and A/B reconfiguration positions, while retaining the contract's explicit limit that a new return ID need not equal the earlier take ID. Rehash all changed source pins into a new prelaunch manifest, repeat independent static review, and only then consider a clean actual SSH0 `-PreflightOnly` call. The accepted parent source/raw pins and frozen contract remain unchanged.
