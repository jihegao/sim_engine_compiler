# C05.var03 v1.0.1 draft validator review — NO_GO_VALIDATOR

This review concerns the **unapproved** `validate_native_cli.py` draft, 15,965 bytes, SHA-256 `6199217e26e690dffd1c38ae1778f0931a340770b96c5d406d80513235924c48`. The v1.0.1 contract remains SHA-256 `cc3aa75b3c4f6cec8fff57c0de28abf9ed552f4c0bc836e581295856ca30f283`. The separate draft-source NO_GO on `MissionSystem` B `PRI=1` versus frozen `PRI=2` also remains open. No native run or manifest approval had occurred at this review.

1. `records()` retains only lines beginning `Time:` and discards indented continuation lines. The accepted C05 capacity-two model.log places `Availability test on <MISSION-CREW ...> request for: 1 OK` on the continuation immediately after the timestamped `system resource availability test` line. The draft's radio witness therefore cannot see an analogous `MISSION-RADIO request for: 1 failed` and would reject a valid negative arm.
2. `full_report()` counts a cell as inspected when it has a valid JSON scalar, but ten dynamic `SystemResults` fields are exempted from full row comparison and get only two integrals and one terminal check. Changed interior `NSYRY`, `NSYMC`, `NSYMR`, `FTMO`, `NRCFG`, `STREQ`, or `STACC` cells can evade the frozen every-cell physical ledger gate. The generic `near()` tolerance also applies to identifiers/counts instead of field-aware exactness.
3. It compares supposedly stable `StockTotalResults` cells to A16 by row. A16 has local reconfiguration demand markers (`ROS`, `ROST`, `WT`, `WTT`) in the h19 bin for its second mission. The proposed child has one h7 shared mission and need not repeat h19 demand. Native demand events, not A16 row position, must generate all 72 stock-bin expectations. The draft separately equates `NDR`/`NWT` to stock takes rather than demand events, which is not the same rule under shortage.
4. `C05_NEG` uses the accepted C05 capacity-one report as a reference without a literal seal in the frozen v1.0.1 `accepted_native_runs`; the contract pins the C05 capacity-two run. Remove that unpinned oracle or pin it in a prospective, separately reviewed contract. The negative summary can instead be derived from the no-launch/no-success event ledger under the current contract.
5. The negative event gate checks only for absence of a two-system h8 launch token; it should reject **any** one-system launch or success because the frozen source requires `MissionType.NOS=MNOS=2` and `MissionSystem.MNOS=1` for each A and B configuration.

Recovery: preserve this draft byte identity, fix source B priority and rebuild the pair; then group event continuations, derive every report cell from accepted source and observed event/stock/resource state with field-specific precision, remove the unpinned report reference, add exact typed-formation and per-cell tamper tests, and seek a fresh exact-file review.
