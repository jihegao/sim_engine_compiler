# D05.var01 two-worker capacity control, v1.0.0

This package compares two `P-MAINT` workers with the accepted [D05 one-worker case](../D05-maintenance-competition-v1.0.0/cli-scope-signoff-2026-09-30.md). The [exact parent diff](parent-diff.json) changes only `ResourceAllocation.RQTY=1→2` as a behavior field; `ProblemDescription.PDESC` and `Resource.DESCR` are labels. The parent input SHA-256 is `4443d057ade36010a84186aa0f9ac8279886563db190ed80699b7fe48ad2baad`, and this input SHA-256 is `a29857331ed02bf4150c04be71d34a5f84ce66e6e76f1db27bdd94a14320686a`.

Both fixed-seed runs have the same one critical failure at hour 22.6835, an aborted second mission, a five-hour direct repair from 23–28, two PM task objects opened at 24, and successful first and third missions. With one worker, actual PM work is 28–29 and 29–30, with five accumulated worker-wait hours. With two workers, the healthy aircraft's PM performs 24–25 **while repair is still working**, and the failed aircraft's PM performs 28–29 after its own repair. Worker wait is zero in the two-worker report. Two workers are free and two aircraft ready at hour 36. The failed aircraft's PM still waits for its own critical repair; zero worker wait does not mean all PM work begins at 24.

The [CLI sign-off](cli-scope-signoff-2026-09-30.md) records native hashes, event/resource ledgers, author and independent pair replay, and limits. `python build.py` verifies the frozen child input; `python describe_diff.py` verifies the exact parent delta. Use `run_native_ssh.ps1` only from the pinned session-0 SSH context with a new `-RunId`; it guards the existing GUI PID 13340 and host-wide mutex, and stores raw artifacts in ignored local `runs/`. `python validate_pair.py --output review/<new-name>.json` replays the accepted pair without invoking SIMLOX. Changing the worker quantity, seed, repair length, PM tolerance, or mission timing requires new predicted bounds and native evidence.

This comparison covers D05.var01's one-versus-two worker boundary in one fixed fault/PM schedule. Zero-worker capacity, same-time failure/PM boundaries, alternative priority classes, critical PM, failed mission cancellation caused by maintenance wait, later cycles, GUI visual behavior and cross-engine equivalence remain unverified.
