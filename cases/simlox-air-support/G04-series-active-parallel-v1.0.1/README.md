# G04 explicit series and active parallel RBD

This bounded pair derives directly from the accepted [G02.var01 two-position case](../G02-var01-position-modes-v1.0.0/cli-scope-signoff-2026-10-01.md), with [G01.var01](../G01-var01-lru-sru-v1.0.1/cli-scope-signoff-2026-10-01.md) as an accepted item-structure prerequisite. The parent system has POS-A and POS-B, each carrying the same LRU type with an explicit position-specific failure mode and half-hour direct system CM. Both G04 arms retain its aircraft, three 8–10/20–22/32–34-hour missions, seed 1, one replication, and 36-hour result window. They activate `Control.RELOP=RBD`, link `BASIC-MISSION` and the aircraft to `G04-OPS`, and map the system to an RBD rooted in the two positions. The series arm requires both positions; the active parallel arm has `NBREQ=1`, `NBOP=2`, `TSWOV=0`, and `ONLM=N`.

`build.py` and `describe_diff.py` verify the frozen input hashes and complete parent delta. The installed SIMLOX manual, SHA-256 `39427027c46809a9ce9ebcb9be04e7396d96746e42a6f8c7c0ba2ddc294ef8a3`, describes series/parallel function on physical pages 196–200 and 448–459; its worked example on pages 767–770 shows mission and materiel mode links. The installed dictionary SHA-256 is `11a61537c95489e32742d98ca8532b42aa1ec728c270009e5b1a8643325e96d0`. These installed proprietary sources are not distributed here.

An earlier v1.0.0 series diagnostic imported and exported but failed native conversion with two error #464 records: POS-A and POS-B had no matching leaf `MaterielOperationalModes` rows for `<DEFAULT>`. Its SXO is four bytes and it has no valid simulation result. `diagnostic-predecessor.json` and the exact failed input preserve that attempt; its raw run remains local and excluded. Version 1.0.1 gives each leaf its `G04-OPS` materiel mode with an empty child RBID, as shown in the manual example, and references that mode in the block structure.

Both v1.0.1 arms completed guarded session-0 SSH native import, export, calculation, report and roundtrip while GUI PID 13340 stayed responsive. Conversion errors were zero with only inherited logging warning #108. All 23 row-containing authored tables roundtripped exactly in each arm. The same three position-specific failures occur at 8.62763, 20.8222 and 33.0996 hours. In series, each is critical and aborts its mission. In active parallel, each isolated branch failure is noncritical while the other position functions, so all three missions succeed at hours 10, 22 and 34. With `ONLM=N`, the direct half-hour CM starts after each mission ends; the aircraft ends ready in both arms. Each report has 72 aligned half-hour System and Stock bins, three failures, three completed repairs, 1.5 hours of system repair and zero stock demand or backorder. The series event log is byte-identical to the accepted G02 parent. Twenty-four raw files are sealed locally across the two runs; `evidence-index.json` records their paths and SHA-256 hashes.

Run `python build.py`, `python describe_diff.py`, `python validate_native.py`, and `python make_evidence_index.py` from this directory to replay the source and local evidence checks. For a fresh native run, call `run_native_ssh.ps1` from authenticated session-0 SSH with `-Arm series` or `-Arm parallel` and a new run ID. The runner guards the host-wide Issue #18 mutex and the existing GUI.

This fixed seed observes only one failed branch at a time. It does not establish behavior when both branches fail together, other `NBREQ` values, passive switchover, online maintenance, quantities greater than one, nested/bridge/tree RBDs, alternative mission modes, GUI RBD rendering, population reliability or cross-engine equivalence.
