# G02.var04 position-specific preventive maintenance

This bounded four-arm model derives from the accepted G02.var01 two-position aircraft and uses D03's complete calendar-PM task schema. All arms retain the two explicit position failure modes and three scheduled missions, extend the horizon and result windows to 60 hours, and enable global PM. The control has no PM rows. The A-only arm binds `PM-POS-A` to `POS-A` with a 24-hour calendar interval and one-hour base task. The B-only arm binds `PM-POS-B` to `POS-B` with a 36-hour calendar interval and half-hour task. The combined arm includes both. `build.py` reproduces the frozen input bytes and `contract.json` records the predeclared acceptance and limits.

All four accepted arms ran through guarded session-0 SSH under the host-wide Issue #18 mutex while GUI PID 13340 remained present. Native conversion had zero errors and only expected ENLOG warning #108. Exact import/export roundtrips retained all 18 populated business tables in the control and all 23 in each PM arm. The first-replication event log records no PM in the control, A tasks at 24 and 49 hours, B at 36 hours, and all three in the combined arm. System results contain 120 half-hour bins aligned to Stock results. Aggregate `NPMT=NPMS` totals are 0, 2, 1 and 3 respectively, matching the logged PMIDs. There are 12 sealed raw files per accepted arm; `runs/` is local and ignored.

Two first-design diagnostics are excluded. `g02-var04-no-pm-20261002-01` used the earlier source bound to an incomplete builder. `g02-var04-pos-a-only-20261002-01` imported/exported but native conversion rejected missing task definitions with `TaskBreakDown` and `PMLocation` error #2010. The source was corrected to include D03-derived `Tasks` and `SubTaskType` rows, then every arm was rerun with new IDs and source closures. Author validation and independent read-only replay pass; the latter checked 282/282 conditions. PR gates are pending.

This fixed-seed result demonstrates only the logged position-bound PM tasks and reconciled report counts in this model. The different failure totals across arms are not interpreted as a causal PM effect. PM quantity/environment propagation, replacement multiplicity, other positions or seeds, GUI visual content and cross-engine parity remain unverified.
