# G05 activated-branch failure event timing

This probe derives from the [accepted G05 half-hour passive standby input](../G05-passive-switchover-v1.0.0/README.md). The sole model parameter change is `RBDParallel.TSWOV` from `0.5` to `8.3` hours, long enough to contain the previously observed roughly 8.122-hour interval from POS-A activation completion to failure if that interval instead began at activation initiation. The problem description also changes. The same seed, three B/A/C positions, one operated branch, fixed hour 8–34 mission, failure modes, repair and stock configuration remain.

`build.py`, `contract.json` and `exact-diff.json` freeze this diagnostic before native execution. The accepted parent input SHA-256 is `d5a38dcb0006f3a2dc6447bdafdeb5c5e5a98b8eb2ccb49db57fa2801ae76c20`; the long input SHA-256 is `13906f9ed1ba3e739072be50a8de93479cb8f339fa8f5ebe2f1b1a7ad20ea4a1`.

The guarded native run completed with exact roundtrip of all 23 populated authored tables. B fails and B→A activation runs from hour 8.94145 to about 17.2414. The model log holds the next-failure sentinel during that switch, then schedules POS-A failure for hour 25.3636 after the switch stops. That is about 8.122 hours after completion, matching the accepted short-switch control. This establishes observed post-completion failure event timing for this fixed configuration; it does not reveal when an internal RNG draw or clock object is created.
